## Overview

The **Superuser role** provides the broadest level of access in the SJRS Library Management System. It is intended for senior system administrators, security personnel, and situations requiring full system visibility. Accounts with this role can access every section of the system and manage all configuration, users, data, and settings.

<Aside type="danger" title="Use With Care">
Changes made as a superuser apply globally and affect all users. Whenever possible, use a librarian or admin role for routine operations.
</Aside>

---

## When the Superuser Role is Used

### Development and Configuration
- Testing features before they are rolled out to other roles
- Adjusting system-wide configuration
- Setting up new institutions or migrating data

### Account and Security Support
- Helping users who are locked out of their accounts
- Resetting security settings when normal recovery methods fail
- Investigating unusual account activity

### System Administration
- Managing the role and permission system
- Approving new user accounts in bulk
- Reviewing system-wide activity and audit logs

## What a Superuser Can Access

Superusers inherit access to everything available to every other role, plus dedicated superuser-only areas.

### Full Library Operations
Everything available to librarians, admins, and deans:
- Catalog management and book inventory
- Order and circulation management
- User accounts, profiles, and approvals
- Analytics and reports
- Penalty and payment handling

## Security & Accountability

### Activity Logging
Every privileged action is recorded. This includes:
- Starting and ending user impersonation sessions
- Approving or revoking emergency access
- Manual interventions and data corrections
- Changes to roles, permissions, and system settings

Each entry records who performed the action, when it happened, and (where applicable) which user account was affected.

### Best Practices

1. **Use the lowest role that gets the job done** — if an admin or librarian account can perform the task, prefer that over using superuser privileges.
2. **Document why you are acting** — especially when modifying another user's account or adjusting system-wide data.
3. **Review logs periodically** — check System Logs and Action Logs to confirm all privileged activity was legitimate.
4. **Protect your account credentials** — require a strong password and enable Multi-Factor Authentication on your superuser account.
5. **Limit the number of superuser accounts** — keep the list as small as the institution can safely operate with.

## Common Workflows

### Resetting a User's MFA When They Lost Their Device
1. Navigate to **Members** (`/dashboard/members`) and locate the user
2. Open the user's record and choose the **Reset MFA** action
3. Instruct the user to set up MFA again at their next login via `/dashboard/mfa-settings`
4. The action is recorded in the audit log

### Configuring Borrow Limits for a User Type
1. Open **Borrow Limits** (`/dashboard/borrow-limits`)
2. Select the user type (Student, Professor, Guest, etc.) you want to configure
3. Set the maximum number of concurrent active loans, the fine-per-day rate, renewal limits, and the reservation claim window
4. Save the changes — they take effect immediately for new loans and reservations

### Approving New User Accounts in Bulk
1. Open the **Members** page (`/dashboard/members`)
2. Filter by status **Pending Approval**
3. Select multiple rows and use the **Bulk Approve** action, or open individual rows and approve one by one
4. Each approved user receives a confirmation email notification
