This guide is for **admins and superusers** who need to understand how the in-app help center operates, verify it is working correctly, and manage the lifecycle of help content for all users.

## Overview

The SJRS LMS Help System provides a lightweight, discoverable entry point to the full documentation library. Rather than duplicating documentation inside the application, the in-app Help page presents a curated set of category cards. Each card links directly out to the corresponding topic on the official documentation site at https://docs.sjrslms.in. This approach ensures content stays current and comprehensive without requiring application deployments for every documentation edit.

All users (regardless of role) see the same seven help categories. The help system does not perform role-based filtering of categories or content.

## Help Page URL

Users can reach the help page directly at: `/help`

## Available Help Categories

The in-app help page displays seven category cards. Each card includes an icon, a short description, and an external link to the full documentation on the docs site.

| Category | What it covers | Docs destination |
|----------|----------------|------------------|
| **Borrowing** | How to borrow books, borrowing limits, and order requests | `https://docs.sjrslms.in/features/faqs/borrowing` |
| **Returns & Fines** | Returning books, late fees, and lost item procedures | `https://docs.sjrslms.in/features/faqs/returns-fines` |
| **Account Management** | Registration, login, and profile updates | `https://docs.sjrslms.in/features/faqs/account-management` |
| **Payments** | Paying fines and supported payment methods | `https://docs.sjrslms.in/features/faqs/payments` |
| **Library Rules** | Operating hours, access policies, and facility rules | `https://docs.sjrslms.in/features/faqs/library-rules` |
| **Digital Resources** | Digital resources, printing, and remote access | `https://docs.sjrslms.in/features/faqs/digital-resources` |
| **Special Services** | Research privileges, donations, and special requests | `https://docs.sjrslms.in/features/faqs/special-services` |

Clicking anywhere on a category card opens the corresponding docs page in a new browser tab.

## Access Methods

Users can reach the help content in three ways:

### 1. Top Navigation Info Icon
Users can click the info icon in the top navigation area to open the help overview.

### 2. Keyboard Shortcut (?)
From anywhere in the application (except when actively typing in an input, textarea, or editable field), pressing **`?`** (Shift + /) toggles the help drawer. The help drawer appears as a right-side panel with quick links to all seven categories and a handful of quick tips. Pressing **`?`** again closes the drawer.

### 3. Direct URL
Navigating directly to `/help` in the browser address bar opens the full help page with all seven category cards laid out in a grid.

## How to Verify Help Works

To confirm the help system is functioning as expected:

1. Navigate to `/help`. You should see the page header "Help & Documentation" followed by seven category cards in a grid layout.
2. Verify each card displays an icon, a title, and a one-line description.
3. Click any category card. It should open the corresponding `https://docs.sjrslms.in/features/faqs/...` page in a new browser tab.
4. Go back to the application. Press **`?`** anywhere outside a text field. The right-side help drawer should open with quick links to the same seven categories.
5. Click a link inside the drawer. It should also open the docs site in a new tab.

## Maintenance

All help content lives on the documentation site at **https://docs.sjrslms.in**. The in-app help system is purely a set of curated entry points (category cards with external links). This means:

- **Content edits** (fixing typos, adding steps, updating screenshots, expanding a topic) are performed on the docs site. No application release is required for documentation-only changes, and the in-app links automatically point to the latest version.

- **Adding or removing categories** (changing which seven cards appear, or changing their titles, descriptions, icons, or destination URLs) requires an application change. The category definitions are part of the application source code and ship through the normal release process.

- **URL verification** is recommended periodically to confirm each of the seven external links still resolves to the correct documentation page. If a docs URL changes (for example, a page is moved or restructured on the docs site), the corresponding in-app link must be updated in source code and released.

## Troubleshooting

### 1. A category link is not working or goes to the wrong page

If clicking a category card opens a broken page, 404, or the wrong documentation topic:
- Verify the destination URL by visiting it directly in a browser (outside the app).
- If the docs page was moved or renamed on the docs site, the fix is to update the destination URL in the application's category definitions and ship it through the normal release process.
- If the URL is correct but the docs site itself is down, treat it as a docs site infrastructure issue rather than an application issue.

### 2. A category card is not showing on the help page

The help page always shows all seven categories to every user. If fewer than seven cards appear:
- Refresh the page (`Ctrl/Cmd + R`) and confirm there are no browser extensions blocking or hiding content.
- If the page is still missing cards after a hard refresh, check the application console for any JavaScript errors that may have interrupted the render.
- Categories are never hidden based on user role. Role-based filtering is not implemented in the help system.

### 3. Documentation content appears outdated

If the information in a linked docs article is stale or incorrect:
- The fix is to update the content on https://docs.sjrslms.in. No application change is needed.
- After editing the docs page, the in-app link automatically points to the updated version since it references the same URL.
- If you are unsure whether a docs update has propagated, do a hard refresh (`Ctrl/Cmd + Shift + R`) on the docs site page to bypass any cached copy.
