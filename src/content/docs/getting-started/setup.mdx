## Prerequisites

- Node.js (v22 or higher)
- npm
- Cloudflare account
- Wrangler CLI (`npm install -g wrangler`)

**Note**: This is a **Single Page Application (SPA)** built with React, deployed as a unified Cloudflare Workers app with Static Assets. All routing is handled client-side by React Router.

## Quick Start

### 1. Clone and Install
```bash
git clone https://github.com/PC-Mender/sjrslms.git
cd sjrslms
npm install
```

### 2. Cloudflare Configuration

The `wrangler.toml` file is committed to the repository and contains non-sensitive configuration (routes, D1 bindings, assets config). **Secrets are managed separately** via the Cloudflare Dashboard or `wrangler secret put`.

1. Open `wrangler.toml` and update the `account_id` and `database_id` with your actual Cloudflare values
2. Configure secrets via Wrangler CLI:

```bash
wrangler secret put JWT_SECRET
wrangler secret put JWT_ISS
wrangler secret put JWT_AUD
wrangler secret put MAILJET_API_KEY
wrangler secret put MAILJET_API_SECRET
wrangler secret put TURNSTILE_SECRET_KEY
# Optional: dedicated CSRF secret (falls back to JWT_SECRET if not set)
wrangler secret put CSRF_SECRET
```

### 3. Environment Variables

Copy the example environment file and update with your values:

```bash
cp env.example .env
```

Key variables (see `env.example` for the full list):

```env
VITE_API_BASE_URL=http://localhost:8787
NODE_ENV=development
FRONTEND_URL=http://localhost:3000
```

:::tip
**Option A (recommended)**: Run the Workers API locally with `npm run dev:api` (starts wrangler dev on :8787), then set `VITE_API_BASE_URL=http://localhost:8787`.

For Option A, you also need local Cloudflare Workers secrets. Copy the example file and set at least `JWT_SECRET`:

```bash
cp .dev.vars.example .dev.vars
```

Edit `.dev.vars` and set `JWT_SECRET` to a development secret (at least 32 characters). See `.dev.vars.example` for the full list of local dev variables.

**Option B**: Use a deployed staging API — set `VITE_API_BASE_URL=https://your-staging-domain.com`. No local backend needed.
:::

### 4. Cloudflare Resources

Create the required Cloudflare resources and update `wrangler.toml` with the returned IDs:

```bash
# D1 database
wrangler d1 create your-database-name
# Update database_id in wrangler.toml with the returned ID

# R2 bucket for file uploads
wrangler r2 bucket create your-assets-bucket
wrangler r2 bucket create your-assets-bucket-dev  # preview/dev bucket

# KV namespace for caching
wrangler kv namespace create CACHE
# Update the id in wrangler.toml [[kv_namespaces]] with the returned ID
```

### 5. Database Setup (Remote-first)

Remote-first policy: use the remote D1 database even during local development.

The `sql/d1-schema.sql` file is a consolidated schema that includes all applied migrations. Use it for initial setup:

```bash
# Apply the consolidated schema (remote)
wrangler d1 execute your-database-name --file=sql/d1-schema.sql
```

Check `sql/migrations/README.md` for any pending migrations that haven't been integrated into the main schema yet. Apply those individually if needed.

Optional: If you explicitly need a local preview, you may append `--local` to the execute commands.

### 6. Start Development

```bash
npm run dev
```

Visit `http://localhost:3000` to see your application!

## Security Best Practices

1. Use environment variables for sensitive data
2. Never commit real API keys or secrets
3. Use template files for configuration
4. Regularly rotate JWT secrets and API keys
5. Monitor your Cloudflare dashboard for unusual activity

## Files to Never Commit

- `.env*` files
- `.dev.vars` (local Cloudflare secrets)
- `node_modules/`
- Build artifacts (`dist/`, `build/`)
- Log files
- IDE-specific files
- `.wrangler/` (local Wrangler cache)

:::note
`wrangler.toml` **is** committed to the repository — it contains only non-sensitive configuration. Secrets are managed via Cloudflare Dashboard or `wrangler secret put`.
:::

## Troubleshooting

If you encounter issues:

1. Check that `wrangler.toml` is properly configured
2. Verify your Cloudflare account has the necessary permissions
3. Ensure your database is properly set up
4. Check the Cloudflare Workers dashboard for deployment status
