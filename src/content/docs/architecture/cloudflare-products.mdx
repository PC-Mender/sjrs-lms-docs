## Overview

This document provides a comprehensive guide to all Cloudflare products used in the SJRS Library Management System, including setup, configuration, and best practices.

**Note**: The SJRS LMS is a **Single Page Application (SPA)** built with React. All client-side routing is handled by React Router, and the server serves the main `index.html` for all routes.

The SPA's static files are served by the **same Worker** via the `ASSETS` static-assets binding — there is no separate Cloudflare Pages deployment.

## Cloudflare Workers with Static Assets

### What It Is
Cloudflare Workers with Static Assets is a unified deployment model that combines serverless functions with static asset hosting in a single Worker.

### Features Used
- **Unified Deployment**: Single deployment for both frontend and backend
- **Static Asset Serving**: Serves React application directly from Workers
- **API Integration**: Backend API and static assets in one deployment
- **Global CDN**: Content delivered from 200+ locations worldwide
- **Automatic SSL/TLS**: Built-in security certificates
- **Edge Computing**: Both API and assets served from the edge

### Configuration
```toml
# wrangler.toml
name = "sjrslms"
main = "functions/index.ts"
compatibility_date = "2024-09-23"
compatibility_flags = ["nodejs_compat"]

# Static Assets configuration for unified deployment
[assets]
directory = "./dist"
html_handling = "auto-trailing-slash"
binding = "ASSETS"
```

### Benefits
- **Simplified Architecture**: Single deployment for full-stack application
- **Global Performance**: &lt;50ms latency worldwide for both API and assets
- **Cost Effective**: Unified billing and resource usage
- **Developer Friendly**: Single `npm run release` command
- **Zero Configuration**: Automatic HTTPS, CDN, and security
- **Easier Maintenance**: One deployment to manage instead of two

- **Rate Limiting**: API request throttling (essential for security)

### Benefits
- **Low Latency**: &lt;10ms read times
- **Global Distribution**: Available worldwide
- **Automatic Expiration**: TTL-based cleanup
- **High Availability**: 99.9% uptime SLA

## Cloudflare Email Service (send_email)

### What It Is
Cloudflare's native email-sending binding, used for the superuser mailbox compose feature. Inbound mail arrives via **Cloudflare Email Routing** and is parsed with `postal-mime`.

### Configuration
```toml
# wrangler.toml
[[send_email]]
name = "SJRS_EMAIL"
allowed_sender_addresses = ["library@sjrslms.in"]
```

### Usage
```typescript
await env.SJRS_EMAIL.send(message); // functions/services/email/email-sender.ts
```

Related variables: `SJRS_FROM_EMAIL`, `SJRS_FROM_NAME`, `SJRS_ALLOWED_SENDERS`, `SJRS_INBOX_ALLOWLIST`, `SJRS_EMAIL_DAILY_QUOTA`, and retention settings — see [Environment Variables](/deployment/environment-variables).

### Scheduled Jobs (cron)
Background work runs via the `[triggers] crons = ["0 2 * * *"]` trigger — handlers live in `functions/scheduled/` (overdue reminders, penalty calculation, retention cleanup, badge evaluation, GitHub issue sync, token/log cleanup). No Queues or Durable Objects are currently provisioned.

## Email Service Architecture

### Overview
The email system uses two sending paths plus inbound routing:

1. **Mailjet** — transactional/notification emails (account confirmation, password reset, loan/order/payment/system notifications) via `functions/utilities/email-service.ts` and the `/api/v1/email/send-*` endpoints.
2. **Cloudflare Email Service (`SJRS_EMAIL` binding)** — the superuser mailbox compose feature (`/dashboard/email`) sends through the `send_email` binding.
3. **Cloudflare Email Routing** — inbound mail is parsed with `postal-mime` in `functions/services/email/email-receiver.ts`, sanitized, stored in D1 (`email_inbox`), with attachments in R2 (`email-attachments/`).

There is no queue-based sending pipeline — outbound email is sent synchronously from the Worker.

### Architecture Strategy

####  Account-Related Emails (Direct Mailjet)
- **Purpose**: Registration confirmation, password reset, email verification
- **Reason**: Immediate feedback needed, low volume
- **Implementation**: Direct API calls to Mailjet

```typescript
// Direct Mailjet for account emails
async function sendConfirmationEmail(email: string, firstName: string, token: string, env: any) {
  const emailData = {
    Messages: [{
      From: { Email: env.MAILJET_FROM_EMAIL, Name: "SJRS LMS" },
      To: [{ Email: email, Name: firstName }],
      Subject: "Confirm Your Email Address",
      HTMLPart: `<h2>Welcome to SJRS LMS!</h2>...`
    }]
  };

  const response = await fetch('https://api.mailjet.com/v3.1/send', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Basic ${btoa(`${env.MAILJET_API_KEY}:${env.MAILJET_API_SECRET}`)}`
    },
    body: JSON.stringify(emailData)
  });
}
```

####  Transactional Emails (Mailjet)
- **Purpose**: Loan notifications, return reminders, overdue notices, system notifications
- **Implementation**: Synchronous Mailjet sends via `functions/utilities/email-service.ts`; overdue reminders and similar batch mail are triggered by the daily cron trigger in `functions/scheduled/`
- Retry behavior is governed by `EMAIL_RETRY_ATTEMPTS`

####  Mailbox Compose (Cloudflare Email Service)
- **Purpose**: Superuser outbound mailbox (`/dashboard/email` → `POST /api/v1/email/compose`)
- **Implementation**: `send_email` binding via `functions/services/email/email-sender.ts`; per-user daily quota (`SJRS_EMAIL_DAILY_QUOTA`), sender allowlist enforcement, sent log in D1
- **Drafts**: body HTML sanitized on persistence (allowlist `xss` sanitizer + CSS property allowlist)

####  Inbound Mail (Email Routing)
- **Purpose**: Superuser inbox
- **Implementation**: Cloudflare Email Routing → Worker `email()` handler → `postal-mime` parsing → D1 `email_inbox` rows (allowlisted recipients via `SJRS_INBOX_ALLOWLIST`), attachments to R2
- **Defense in depth**: size limits, sender/envelope separation, HTML sanitization before storage, duplicate `message_id` protection, fail-closed rejects

### Email Service Comparison

| Approach | Use Case | Benefits |
|----------|----------|----------|
| **Mailjet** | Account + transactional emails | Template support, analytics, established sender reputation |
| **Cloudflare Email Service** | Mailbox compose | Native binding, no external API key, sender allowlist |
| **Email Routing** | Inbound mailbox | Native Workers integration, no mailbox hosting needed |

### Environment Variables Required
```bash
# Mailjet Configuration (for both direct and queue)
MAILJET_API_KEY=your_mailjet_api_key
MAILJET_API_SECRET=your_mailjet_api_secret
MAILJET_FROM_EMAIL=noreply@yourdomain.com

# Frontend URL
FRONTEND_URL=https://your-frontend-domain.com

# API Configuration
VITE_API_BASE_URL=https://your-api-domain.com
```

### Best Practices

#### 1. Choose the Right Approach
- **Account + transactional emails** → Mailjet
- **Mailbox compose (superuser)** → Cloudflare Email Service (`SJRS_EMAIL`)
- **Inbound mail** → Cloudflare Email Routing → Worker `email()` handler

#### 2. Error Handling
```typescript
// Direct Mailjet error handling
try {
  await sendConfirmationEmail(email, name, token, env);
} catch (error) {
  console.error('Failed to send confirmation email:', error);
  // Don't break registration flow
}
```

#### 3. Monitoring
- **Mailjet**: Log success/failure immediately; Mailjet dashboard for delivery analytics
- **Mailbox**: sent log table (`/api/v1/email/history`) records outcomes

### Migration Guide

#### From Generic Email Service to Mailjet Backend
```typescript
// Before (generic email service)
const response = await fetch('https://api.email-service.com/send', {
  headers: { 'X-API-Key': env.EMAIL_API_KEY }
});

// After (Mailjet backend)
const response = await fetch('https://api.mailjet.com/v3.1/send', {
  headers: {
    'Content-Type': 'application/json',
    'Authorization': `Basic ${btoa(`${env.MAILJET_API_KEY}:${env.MAILJET_API_SECRET}`)}`
  }
});
```

This split keeps **transactional mail on a proven ESP (Mailjet)** while the **superuser mailbox runs entirely on Cloudflare primitives** (send_email + Email Routing + D1 + R2).
